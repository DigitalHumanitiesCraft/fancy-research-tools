# research-ui-evaluate

Read the task brief, [testing contract](../../../knowledge/testing.md) and relevant [data contract](../../../knowledge/data.md). Apply the current [operator default profile](../../../knowledge/design.md#operator-default-profile), including its interface copy constraint. The [comparison protocol](../../../benchmarks/ui-concepts-protocol.md) defines comparable tasks and the [benchmark procedure](../../../benchmarks/README.md#preserve-a-run) preserves evidence. All required project sources are local.

## Establish the run

Record source/build identity, data identity, starting state and available browser capabilities. Use isolated working data. For comparisons, keep the task and material equivalent and record prior exposure, order and assistance. Retain the baseline before changing it. When independently reviewing another agent's work, begin with the brief and rendered interface without that agent's quality verdict or suspected cause.

## Complete the research action

Operate the interface before diagnosing implementation. Follow one complete path from finding material through interpretation to the retained outcome. Record actual actions, detours, errors and assistance. Compare source values with their visible representation, selected identities and actual exported bytes. Check the case's important qualifiers, missingness, dates, places, attribution and production status at the affected field. A successful interaction can still communicate a false claim.

Inspect the dense and scrolled states as well as entry. Check whether primary information is directly useful, whether disclosure hides a prerequisite for the next action, and whether repeated labels or controls obscure comparison. Additional provenance may legitimately remain optional. Evaluate each element against the task rather than counting controls or disclosures.

Compare rendered copy and controls against the named profile, including its small repeated decisions. Cite the owning rule and an observed instance for a mismatch. A general judgement such as “compact” does not establish compliance with identifier, separator or status-icon decisions.

## Exercise alternate operation and recovery

Repeat the consequential action with a keyboard. Inspect meaningful reading order, focus, narrow reflow and text enlargement using the testing contract. Check icon explanations through focus and touch, including production status, and keep essential meaning available without hover. Exercise relevant empty results, reversal, interruption and invalid imports with expendable copies. Inspect actual download and reopen behaviour when they belong to the task.

Report unavailable browser, screen-reader or touch observations as unexecuted. Screenshots show appearance, automated accessibility checks cover their tested rules, and human observation supplies evidence of research fitness and experience.

## Record findings

For each finding retain the task, start state, reproducible actions, observed consequence and evidence path. Separate observation from proposed cause. Record correctness, interaction, accessibility and human acceptance separately, with no aggregate agent quality score. Use measured timings only. Preserve negative evidence and pass bounded corrections to the improvement procedure after the baseline is recorded.

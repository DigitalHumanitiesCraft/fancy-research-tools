# research-ui-evaluate

Read the task brief, settled [purpose](../../../knowledge/project.md#purpose), [UI acceptance protocol](../../../knowledge/testing.md#ui-acceptance-protocol), current [operator profile](../../../knowledge/design.md#operator-default-profile) and affected data contract. These local sources define the task and its rules. For a concept comparison, also read the [comparison protocol](../../../benchmarks/ui-concepts-protocol.md).

## Establish an independent run

Record source/build identity, data identity, starting state and available browser capabilities. Use isolated working data. Preserve a baseline before changes. For comparisons, hold task and material equivalent and record order, prior exposure and assistance. An independent reviewer starts with the task and rendered interface without the implementing agent's verdict or suspected cause.

## Operate before diagnosis

Complete the research action through its retained outcome using the acceptance protocol. Record actual actions, detours and errors. Compare original source values, displayed claims, selected identities and exported bytes. A successful click can still communicate a false claim.

Inspect the dense and scrolled states. Trace repeated content across header, sidebar, view and detail, then inspect component callers to explain the observation. Distinguish duplicated information from different populations or decisions. Check whether hidden detail is a prerequisite for the next action. Cite the owning design rule and an observed instance for a profile mismatch.

Exercise consequential keyboard operation, relevant recovery and actual download/reopen when the task provides them. Report unavailable browser, touch or screen-reader observations as unexecuted. The protocol defines what each evidence type can establish.

## Record findings

Preserve the task, start state, reproducible actions, observed consequence and evidence path for each finding. Separate the observation from its proposed cause. Record correctness, interaction, accessibility and human acceptance separately, with measured timings only and no aggregate agent quality score. Retain negative findings and the baseline using the [benchmark procedure](../../../benchmarks/README.md#preserve-a-run) before passing bounded corrections to improvement.

# research-ui-evaluate

Read the task brief and knowledge/testing.md. Use isolated browser state and the same data and task for comparisons. Operate the interface before inspecting implementation. Record start state, actions, outcome, detours, assistance, errors and downloaded evidence. Separate correctness, research fitness, interaction usability and visual/experiential judgement. Check keyboard, narrow screens and recovery. Screenshots support visual inspection, not task success. Agent opinions are hypotheses; enjoyment and researcher acceptance require human evidence. Do not invent timings, participants or scores. Report severity by consequence and reproducible steps. Compare concepts fairly and acknowledge order/learning effects. No changes during a baseline review; propose focused improvements after recording it.

Check every rendered page and section heading against the interface copy constraint in knowledge/design.md. Any introductory subline, including an informative subtitle, fails design acceptance. Record the affected route and heading.

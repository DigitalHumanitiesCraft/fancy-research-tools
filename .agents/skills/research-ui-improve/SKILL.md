# research-ui-improve

Read the recorded task evaluation and current design contract. Identify the underlying task, data, interaction or implementation cause before changing presentation. Form a falsifiable change hypothesis and preserve a recoverable baseline. Prioritise data loss or misleading evidence, then task blockers, then clarity and visual refinement. Implement a bounded change and repeat the affected tasks with the same material. Record fixed, unresolved and newly introduced issues separately. Keep accepted decisions, observations and reusable pattern hypotheses distinct in project knowledge. Preserve negative findings; do not turn one pilot solution into a universal rule. Human research acceptance cannot be inferred from tests.

Preserve the interface copy constraint in knowledge/design.md through every iteration: remove introductory sublines and do not reintroduce them as informative subtitles or nearby banners.
